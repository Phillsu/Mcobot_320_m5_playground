# MyCobot320 控制專案（4test）

以 Python + [pymycobot](https://github.com/elephantrobotics/pymycobot) 控制 **Elephant Robotics myCobot320 (M5 版)** 六軸機械臂的實作專案，包含：通訊體檢、運動測試、Xbox 手把搖操、攝影機手勢搖操。

```
demo.py            入門範例：串口自動偵測 + Atom RGB 燈循環測試
demo_robust.py     運動測試（讀角度 → J1 轉 40° → 自動回到起始姿態）
mc_diag.py         分層體檢（主控 / Atom / 舵機供電）
detect_gamepad.py  Xbox 手把連線偵測（XInput，零依賴）
xbox_teleop.py     Xbox 手把搖桿遙控六關節
hand_teleop.py     筆電攝影機手勢遙控末端執行器（MediaPipe）
```

---

## 1. 硬體需求

| 項目 | 說明 |
|---|---|
| 機械臂 | myCobot320 **M5 版**（M5Stack 主控 + Atom 子控制器） |
| 電源 | 原廠電源適配器（**須一直接著**，只插 USB 無法啟動主控） |
| 連接線 | **Type-C → USB-A 數據線**（Type-C 插機械臂主控 M5Stack 的口、USB-A 插電腦；只支援充電的線沒有 COM 口） |
| 系統 | Windows（手把控制走 XInput） |
| 手把(選) | Xbox 手把（有線 USB 或無線配對） |
| 攝影機(選) | 筆電內建或外接 camera |

> ⚠️ 首次插線後請到「裝置管理員 → 連接埠 (COM 和 LPT)」確認出現 `USB-Enhanced-SERIAL CH9102 (COMx)`。換 USB 孔後 COM 號碼可能改變——本專案所有腳本都會**自動偵測 CH9102**，不需手動改號。

## 2. 環境建置

專案虛擬環境位於 `.venv`（uv 建立，Python 3.12）。

```bash
cd D:/RBT/4test

# 已安裝的核心套件（pymycobot 4.0.6 / pyserial 3.5 / numpy）
uv pip install --python .venv/Scripts/python.exe pymycobot

# 手勢搖操（hand_teleop.py）才需要；其餘腳本可不裝
uv pip install --python .venv/Scripts/python.exe mediapipe opencv-python
```

> ℹ️ **mediapipe 用新版即可（0.10.30+/1.x，本專案實測 1.0.1）**。`hand_teleop.py` 使用新版 **tasks API（HandLandmarker）**，不再依賴已被新版移除的 `mp.solutions.hands` 舊 API。
> 首次執行 `hand_teleop.py` 會自動下載手部模型 `hand_landmarker.task`（約 7MB）到 `models/` 目錄；若自動下載失敗，手動下載後放到該路徑即可（下載網址會印在錯誤訊息中）。

執行腳本統一用：

```bash
python <script.py>
```

## 3. 開機 SOP（每次使用前）

1. 將機械臂擺成**舒展姿態**（關節不要蜷縮互頂）
2. 接上電源，等待 M5 螢幕完成啟動，**確認顯示 `Atom: ok`**
3. 確認**急停按鈕已旋轉彈出（釋放）**——按下會切斷舵機供電
4. 確認急停旁的 Atom LED 燈板有亮、關節有扭力
5. 插好 USB 數據線 → 電腦出現 CH9102 COM 口
6. 再執行程式

## 4. 各腳本說明

### 4.1 `demo_robust.py` — 運動測試（推薦日常使用）

自動偵測串口 → 讀取 6 軸角度（含重試）→ 舵機未上電自動 `power_on()` → 記錄起始姿態 → **J1 轉到 40°** → 測試完成**自動回到起始姿態**並回讀驗證（誤差 < 2°）。

```bash
python demo_robust.py
```

正常輸出結尾：

```
回到原位后关节角度: [0.0, 0.0, ...]   ← 與起始一致
✔ 測試完成，機械臂已回到起始姿態
```

### 4.2 `demo.py` — 入門 RGB 燈範例

初始化機械臂後，讓 Atom RGB 燈**藍 → 紅 → 綠**循環 7 次（每色 2 秒）。適合剛打通通訊時確認連線。

```bash
python demo.py
```

### 4.3 `mc_diag.py` — 分層體檢（出問題先跑這個）

依序探測四個關鍵層並給出診斷結論：

```
get_basic_version      → 主控 Basic 固件版本（2.4 為正常）
is_controller_connected→ Atom 連線（1=通 0=斷 -1=錯誤）
get_atom_version       → Atom 固件版本
is_power_on            → 舵機供電（1=開 0=關 -1=錯誤）
```

```bash
python mc_diag.py
```

全部通過會印 `✔ 一切正常，可執行運動指令`；任一層異常會直接告訴你該查什麼。

### 4.4 `detect_gamepad.py` — Xbox 手把偵測

掃描 XInput UserIndex 0~3，列出已連接的手把，接著即時顯示 6 秒按鍵 / 搖桿 / 扳機數值。

```bash
python detect_gamepad.py
```

看到 `UserIndex x: >>> 已連接 <<<` 即代表手把可用。

### 4.5 `xbox_teleop.py` — Xbox 手把搖操六關節

Windows XInput + pymycobot，**零第三方依賴**（手把資料直接走系統 DLL）。控制週期 10Hz，含死區、軟限位、斷線保護、防漂移校正。

```bash
python xbox_teleop.py
```

| 手把 | 動作 |
|---|---|
| 左搖桿 X / Y | J1 底座旋轉 / J2 肩 |
| 右搖桿 Y / X | J3 肘 / J4 手腕旋轉 |
| LB / RB（按住） | J5 反轉 / 正轉 |
| LT / RT（按住） | J6 反轉 / 正轉（推越深越快） |
| **X** | 切速度檔：慢 / 中 / 快 |
| **A** | 回到 home（啟動時位置） |
| **Y** | 把當前位置設為新 home |
| **BACK** | 退出：倒數 3 秒（印在終端機）後**所有關節回 0°（歸零）**再關閉；倒數中按 Ctrl+C 可跳過歸零直接關閉 |
| **Ctrl+C** | 退出：立即歸零後關閉（歸零中再按一次可跳過） |

安全機制：搖桿死區防抖、關節軟限位（J1~J5 ±165°、J6 ±175°，官方範圍）、手把斷線 3 秒自動退出（同樣倒數歸零）、每 2 秒用實際讀數校正防漂移、退出時「延遲 3 秒 → 關節全回 0°」自動歸零（改檔頂 `EXIT_DELAY` 可調延遲秒數，`ZERO_SPEED` 調歸零速度）。

> 若某關節方向與搖桿相反：編輯 `xbox_teleop.py` 上方 `STICK_MAP` / `BUMP_MAP` / `TRIG_MAP` 中的 `±1` 方向符號即可。

### 4.6 `hand_teleop.py` — 攝影機手勢搖操末端執行器

MediaPipe 手掌偵測，**絕對游標式**控制末端（TCP）座標：畫面正中央 = 中性點，掌心偏移量直接映射成末端「相對零位的絕對目標」：

| 手掌動作 | 末端動作 |
|---|---|
| 左右移動 | Y 軸平移 |
| 上下移動 | Z 軸平移 |
| 往鏡頭推 / 拉 | X 軸（前進 / 後退） |
| 滾轉（像轉方向盤） | 末端繞自身軸滾轉 RZ |

```bash
# 先跑預覽模式（不連機械臂），確認鏡頭與手勢偵測正常
hand_teleop.py --preview

# 正式搖操
hand_teleop.py --cam 0

# 只測攝影機能不能開（無視窗）
hand_teleop.py --selftest
```

**啟動流程（不用按任何鍵）**：
1. 對準鏡頭張開手掌，把它移到畫面**中央圓圈**內
2. 停留約 **0.6 秒** → 自動校準（快照零位 + 深度/滾轉基準）並啟動
3. 開始移動手掌遙操；**掌心回到中心圓 → 末端回到零位**
   - 手追丟 >1.5 秒會解除啟動，需回中心圓重新校準
   - 手追丟 >0.3 秒（短暫被擋）→ 先回中心圓才恢復動作，防止暴衝

| 鍵盤 | 動作 |
|---|---|
| **R** | 重設零位：機械臂「現在位置」變成中性點（掌心在場會一併校準基準） |
| **1~4** | 翻轉 左右 / 上下 / 前後 / 滾轉 各軸方向（鏡射校正） |
| **0** | 回到啟動位置（home）並設為零位 |
| **Q** / ESC | 退出：倒數 3 秒（畫面顯示）後**所有關節回 0°（歸零）**再關閉。倒數中：再按一次 Q/ESC = 立即歸零退出；按其他鍵 = 取消 |
| Ctrl+C | 退出：立即歸零後關閉（不等倒數） |

安全設計：掌心在中心圓 = 目標 = 零位（機械臂自動回中）、掌心偏移全行程 ±120mm（X 深度 ±100mm）/ ±110°、軟限位 =「零位 ±box」∩「韌體工作空間」、每 tick 目標限步（防暴衝）、`set_fresh_mode(1)` 只執行最新指令避免堆積。

### 4.6.1 控制架構：絕對游標映射（為什麼動作即時、線性、不漂移）

遙操採用「**絕對位置映射**」，不是「速度積分」也不是「每幀回讀當基底」：

- 掌心相對**畫面中央**的偏移（死區外）線性映射成位移：畫面半寬 ⇔ 120mm、log 大小 ±0.55 ⇔ X ±100mm、滾轉 ±90° ⇔ RZ ±110°。目標 = 零位 + 位移，直接 `send_coords mode=0`（~20Hz）。
- **全程不回讀、不積分 → 沒有漂移可校，也就不需要「漂移校正」**。舊版「手停住時回讀校正」會把使用者還沒跑完的指令當漂移取消，造成「拖了沒反應」——新版已整個移除該機制。
- 每 tick 目標限步（≤12mm）+ 目標 EMA 平滑 → 動作連續不暴衝、不抖。
- 掌心移回中心 → 目標回到零位 → 機械臂自己走回來，位置**可重現、可預測**（跟手準確）。

想調整跟手程度/行程，改檔案頂部常數：

| 常數（預設） | 作用 | 調法 |
|---|---|---|
| `BOX_MM` (120) | 左右/上下全行程 (±mm) | 想要動更大就調大 |
| `BOX_X_MM` (100) | 深度全行程 (±mm) | 推拉範圍 |
| `BOX_RZ_DEG` (110) | 滾轉全行程 (±deg) | 轉動範圍 |
| `DEAD_XY / DEAD_FB_LN / DEAD_RZ_DEG` | 死區 | 小動作沒反應就調小 |
| `ENGAGE_R / ENGAGE_T` | 啟動圓半徑 / 停留時間 | 太難啟動就調大 R / 調小 T |
| `TGT_ALPHA` (0.5) | 目標平滑 | 越大越跟手（可能抖）、越小越滑順 |
| `MAX_STEP_MM` (12) | 每 tick 限步 | 動作太慢就調大（上限即速度） |
| `EXIT_DELAY` (3.0) | Q/ESC 後到開始歸零的倒數秒數 | 想快點關就調小（0 = 按了就立即歸零關閉） |
| `ZERO_SPEED` (40) | 退出歸零時 `send_angles` 的速度 | 歸零太快會甩，調小較保險 |

> 畫面是**鏡像**顯示（像照鏡子）：手往畫面右移 → 末端往對應方向動。若方向相反，按數字鍵 1~4 即時翻轉，或直接改檔案頂部 `FLIP_LR` 等常數。

## 5. 初次上手機器手臂：設定實錄（2026-09-02）

> 以下為本專案第一次把這台 myCobot320 M5 弄到「能跑能動」的完整過程紀錄，含當時遇到的問題、逐步診斷與解法。日後若遇到同樣症狀，直接照本章復盤。

### 5.1 當時的場景

機械臂電源一直接著、固件已更新到最新、USB 接上後系統也能正確識別出 `COM3 (USB-Enhanced-SERIAL CH9102)`。環境為 pymycobot 4.0.6 + Python 3.12。但執行讀取關節角度的程式時：

```python
angles = mc.get_angles()
print(angles)      # → -1，而且 send_angle(1, 40, 20) 完全沒反應
```

### 5.2 逐步診斷過程

| 步驟 | 做了什麼 | 結果 | 推論 |
|---|---|---|---|
| 1 | 列出系統串口 | `COM3 = CH9102`，驅動正常 | 串口與驅動沒問題 |
| 2 | 開 debug 模式發讀角度指令 | 電腦成功送出 `fe fe 02 20 fa`，但**機械臂零回應**（`_read` 全空） | 電腦 → 主控這條 USB 鏈路是通的，問題在機械臂那一側 |
| 3 | 硬體四連問：電源 / 固件 / 裝置識別 / COM 口 | 全部正常 | 排除最常見的硬體原因 |
| 4 | 用 `mc_diag.py` 做**分層體檢** | `get_basic_version → 2.4` ✅（主控活著）<br>`is_controller_connected → -1` ❌<br>`get_atom_version → -1` ❌<br>`is_power_on → 0` ❌（舵機供電關） | 主控正常，但**指揮不動底下的 Atom 子控制器** |
| 5 | 看 M5 螢幕畫面 | 顯示 **`Atom: no`**（連 `USB uart` 也顯示 no） | 確認：Atom 層未就緒 → 所有關節指令石沉大海 |
| 6 | **斷電重啟**（機械臂擺舒展姿態，拔電源等 10 秒再上電） | M5 螢幕恢復 **`Atom: ok`**、關節有扭力 | Atom 重新完成初始化 ✅ |
| 7 | 重跑體檢腳本 | **COM3 消失了**——重開機後 USB 重新枚舉把裝置掉了 | USB 線重插即可，不是機械臂的問題 |
| 8 | 重插 USB 數據線 → 跑 `demo_robust.py` | 讀到關節角度、J1 轉到 40°、自動回到起始姿態 | ✅ **整條鏈路打通** |

### 5.3 三個關鍵領悟

1. **`-1` 是症狀，不是原因。** `get_angles()` 只是「等了 N 秒沒收到回應就回 -1」，它本身不告訴你哪一層壞了。要區分「電腦 ⇄ 主控」和「主控 ⇄ Atom」這兩段——分層體檢（`mc_diag.py`）就是為此設計的。
2. **`Atom: ok` 是一切的前提。** 主控 Basic 活著（版本都讀得到）不代表能控制機械臂；必須等螢幕顯示 `Atom: ok` 且舵機有扭力，關節指令才會有作用。錯誤的啟動姿態（關節蜷縮互頂）也可能導致啟動失敗。
3. **USB 重插／重開機後 COM 號碼可能變**（COM3 可能變 COM5…）。所以本專案所有腳本都改成**自動偵測 CH9102 裝置**，從此不用再手動改號碼。

### 5.4 當天定下的「使用守則」

1. 開機 SOP：舒展姿態 → 上電 → **等 M5 螢幕出現 `Atom: ok`** 才跑程式
2. 日常測試用 `demo_robust.py`（自動偵測串口、自動上電、測完自動回位），不要用只寫死 COM3 的舊版
3. 再遇到 `-1`：先看 M5 螢幕是不是 `Atom: ok`、急停有沒有彈出——多半是其中一個沒就位，其次才懷疑線與程式

## 6. 故障排除

| 症狀 | 原因 | 處理 |
|---|---|---|
| `get_angles()` 回 `-1` / 指令無效 | 機械臂無應答，最常見是 Atom 未就緒 | 依序檢查：① M5 螢幕是否 `Atom: ok`（`Atom: no` 表示主控指揮不動 Atom）② 急停是否釋放 ③ 斷電 10 秒重開、擺舒展姿態 |
| 螢幕顯示 `Atom: no` | Atom 子控制器未完成初始化 | 斷電重啟等待螢幕走到 `Atom: ok`；仍失敗用 myStudio 重刷 Atom 固件（燒錄時須上電） |
| 找不到 COM 口 | USB 未插好 / 線只能充電 / 驅動問題 | 換數據線、直連電腦（繞過 HUB）；裝置管理員確認 `USB-Enhanced-SERIAL CH9102` |
| COM 號碼變了 | 換 USB 孔後系統重新分配 | 不需處理——所有腳本自動偵測 CH9102 |
| 舵機不動但螢幕 ok | 舵機供電未開 | 腳本會自動 `power_on()`；手動版請先呼叫 `mc.power_on()` |
| 手把偵測不到 | 未連接 / 走 DirectInput 非 XInput | 檢查 USB 或無線配對；本專案只支援 XInput 手把 |
| `hand_teleop` 報 `module 'mediapipe' has no attribute 'solutions'` | 裝到新版 mediapipe（≥0.10.30 移除舊 API） | 用新版 tasks API 的腳本（現版已改寫，兩者皆相容）；勿再改回 `mp.solutions` 語法 |
| `hand_teleop` 首次執行卡在「下載手部模型」並報錯 | 網路無法連到 Google 模型伺服器 | 依錯誤訊息中的網址手動下載 `hand_landmarker.task`，放到 `D:/RBT/4test/models/` |
| `hand_teleop` 刷一整屏 `send_coords 失敗: ... coord should be -41 ~ 523.9` | 零位(啟動時機械臂位置)太貼近工作空間邊界（例：Z=523.8 已頂到上限 523.9），手一抖就超出韌體容許範圍 | 程式已修正：軟限位改為「零位 ±box ∩ 韌體工作空間」，超限指令會被收斂到合法值、錯誤訊息每 2 秒最多印一次。**根本解：啟動前先把機械臂移到工作空間中段（如 Z≈300）再對準掌心啟動**，上下左右才有行程 |
| `hand_teleop` 完全不跟手、拖了沒動作 | 舊版「速度積分 + 停住時漂移校正」：拖到一半手一回中心，未跑完的指令被當成漂移取消（偏差 >12mm 就回拉目標），反覆拖 = 反覆取消；中心點又是設在「手第一次出現處」而非畫面中心 | 2026-09-02 改為「**絕對游標式**」：中心點固定畫面正中央、掌心對上中心圓 0.6s 自動校準、偏移直接映射絕對目標、**移除漂移校正**。直接重跑即可 |
| `hand_teleop` 動作卡卡的、像小碎步、跟不上手 | 早期版本每幀回讀座標當基底（回讀延遲 → 追尾 + 12Hz 節流）| 已改為絕對目標映射 + 每 tick 限步 + 目標平滑，不回讀不積分。仍不順再依 §4.6.1 調整 `BOX_MM` / `TGT_ALPHA` / `MAX_STEP_MM` / 死區 |

**除錯 SOP**：先跑 `mc_diag.py` 做分層體檢，再跑 `demo_robust.py` 驗證運動，最後才進入搖操程式。

## 7. 安全須知

1. **第一次搖操請用慢速檔、機械臂前方淨空、手放在急停旁**
2. 搖操程式退出會先**倒數 3 秒**再自動**歸零**（所有關節回 0°，機械臂站直）後關閉——倒數期間先退開；不想要自動歸零可在倒數時取消（手勢版按其他鍵取消 / 手把版按 Ctrl+C 跳過）。日常「回到起點」仍用 A（手把）或 0（手勢）觸發，退出歸零不等於回 home
3. 所有控制都有軟限位，但**軟體防呆不取代物理注意**——不要站在機械臂行程範圍內操作
4. 機械臂通電時關節有扭力，搬動前先斷電或釋放急停
